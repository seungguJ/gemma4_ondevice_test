### 작업명

정기결제 후보 알림 POC 구현

### 목적

WalletMate를 개인 AI 비서 방향으로 확장하기 위한 첫 단계로, 지정 금융 알림에서 정기결제 후보를 추출하는 POC를 구현한다.

### 변경 대상 파일

- `app/src/main/java/com/example/gemma4ondevicetest/MainActivity.kt`
- `app/src/main/java/com/example/gemma4ondevicetest/GemmaComposeUi.kt`
- `app/src/main/java/com/example/gemma4ondevicetest/LlmEngine.kt` 또는 필요한 호출 지점
- `app/src/main/java/com/example/gemma4ondevicetest/wallet/*`
- `app/src/main/AndroidManifest.xml`
- 필요 시 관련 문서 최소 범위 갱신

### 구현 요구사항

- 기존 Wallet 카드 사용내역 기능, 일정 기능, 채팅 기능을 깨지 않도록 별도 흐름으로 추가한다.
- 지원 알림 소스는 화이트리스트 기반으로 처리한다.
- 대상은 신한, KB, 삼성카드(모니모), 빗썸, 새마을금고 은행 앱과 카카오톡 알림이다.
- 패키지 허용 규칙은 설정/상수로 관리하고, 실제 패키지명 후보가 불명확하면 구조상 쉽게 추가 가능한 형태로 둔다.
- 모든 알림 중 `광고`가 포함되면 즉시 제외한다.
- 기본 수집 대상은 `결제` 관련 문구가 포함된 알림만으로 제한한다.
- 카카오톡 알림은 수가 많으므로 `결제`뿐 아니라 금융사명(`삼성`, `KB`, `신한`, `빗썸`, `새마을금고` 등)이 함께 들어간 경우만 분석 대상으로 통과시킨다.
- 정기결제 POC는 기존 카드 거래 파서와 분리된 별도 저장/분석 흐름이어야 한다.
- AI 분석 시작 조건은 `충전 중`이며 `배터리 100%`일 때만 허용한다.
- AI 분석이 한 번 성공적으로 완료되면 다음 분석은 24시간 뒤에만 다시 허용한다.
- AI 모델은 평소 상주하면 안 된다.
- 분석 시작 시에만 모델을 로드하고, 분석 종료 후에는 세션 정리와 함께 반드시 모델을 unload/free 한다.
- AI 입력은 배치형으로 수행하고, 최소한 `정기결제 후보 품목`, `반복 결제 가능성 근거`, `놓치기 쉬운 이벤트 여부` 정도를 구조화해서 저장하거나 표시할 수 있어야 한다.
- 앱에 새 scene을 추가해 사용자가 정기결제 후보 목록과 분석 상태를 조회할 수 있게 한다.
- 새 scene은 홈/드로어 등 기존 화면 이동 구조에 맞게 연결한다.
- UI는 POC 수준으로 충분하지만, 현재 앱 톤과 크게 어긋나지 않게 유지한다.

### 금지 사항

- 기존 카드 사용내역 집계 로직을 정기결제 POC와 뒤섞지 말 것
- 알림 수신 시점마다 AI를 즉시 호출하지 말 것
- 배터리 조건 없이 분석하지 말 것
- 모델을 상시 로드 상태로 유지하지 말 것
- 지원하지 않는 모든 알림을 무리하게 분류하려 하지 말 것
- 사용자 기존 변경을 덮어쓰지 말 것

### 검증 방법

- 지원 패키지/문구 필터가 의도대로 동작하는지 샘플 문자열 기준으로 확인
- `광고` 포함 알림이 제외되는지 확인
- 카카오톡은 금융사명 없는 일반 알림이 제외되는지 확인
- 배터리 조건이 맞지 않으면 분석 Worker/흐름이 실행되지 않는지 확인
- 분석 후 모델이 free 되는 코드 경로를 확인
- 새 scene에서 정기결제 후보 결과 또는 빈 상태가 표시되는지 확인
- 가능하면 로컬 빌드 또는 컴파일 검증 수행

### 완료 조건

- 지정 금융 알림 + 카카오톡 금융사명 알림에서 정기결제 후보 POC가 동작한다.
- 충전 중 100% 조건에서만 AI 배치 분석이 실행된다.
- 분석 성공 후 24시간 쿨다운이 지나야 다음 AI 배치 분석이 실행된다.
- 분석 전후 모델 로드/언로드가 명시적으로 구현된다.
- 앱에 정기결제 후보 조회 scene이 추가된다.
- 수정 파일, 검증 결과, 남은 리스크를 보고한다.
