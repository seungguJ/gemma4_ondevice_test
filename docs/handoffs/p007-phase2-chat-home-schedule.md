### 작업명

금융 인사이트 2차 구현: 채팅 내부 데이터 질의, 홈 인사이트, 일정-금융 연결

### 목적

금융, 일정, 채팅이 따로 노는 현재 구조를 개선해 홈 화면 요약, 앱 내부 데이터 질의형 채팅, 일정-금융 연결 시나리오를 추가한다.

### 구현 요구사항

- 이미 추가된 `CardExpenseInsightReport`, `SubscriptionAnalysisReport`, `ScheduleUiState`를 가능한 한 재사용하고, 홈/채팅/일정이 서로 다른 요약 계산을 중복으로 만들지 않는다.
- 홈 화면에 `오늘/이번 달 인사이트` 성격의 요약 블록을 추가한다.
- 홈 인사이트는 최소한 금융 분석 결과와 일정 상태를 함께 반영해야 한다.
- 예: 대표 소비 카테고리, 정기결제 후보 수, 임박 일정 수, 분석 대기 상태.
- 채팅에서 앱 내부 데이터를 읽는 질의를 지원한다.
- 최소한 아래 유형은 처리할 것:
- 이번 달 카드 사용 요약
- 대표 카테고리 요약
- 정기결제 후보 요약
- 다음 일정 요약
- 채팅은 무조건 새 복잡한 tool calling 체계를 만들 필요는 없지만, 사용자가 내부 데이터를 묻는 경우 프롬프트에 해당 요약 데이터를 주입해 응답 품질을 높여야 한다.
- 내부 데이터 주입은 문서 지식 주입과 충돌하지 않게 구성한다.
- 일정 기능에 금융과 연결되는 요약을 추가한다.
- 최소한 일정 화면 또는 일정 요약에 `소비/결제 주의` 맥락 한 줄을 붙일 수 있으면 좋다.
- 예: 정기결제 후보 또는 최근 소비 카테고리와 함께 사용자가 일정을 보는 맥락을 제공.
- 일정과 금융 연결은 과장된 예측이 아니라 현재 저장된 데이터 기반의 보수적 요약이어야 한다.
- 홈/채팅/일정에서 사용하는 공통 금융 인사이트 데이터는 중복 계산보다 재사용을 우선한다.
- 기존 일반 채팅, 지식 문서 응답, 일정 조회, Wallet 화면은 깨지지 않아야 한다.
- 모델 상주 금지 원칙은 동일하게 유지한다.

### 금지 사항

- 허구의 금융 조언 생성 금지
- 저장되지 않은 사용자 데이터가 있는 것처럼 응답하지 말 것
- 문서 라우팅 전체를 새 구조로 뒤엎지 말 것
- 일정 기능을 금융 중심 화면으로 바꾸지 말 것
- 사용자 기존 변경을 덮어쓰지 말 것

### 검증 방법

- 홈 화면에서 금융/일정 인사이트가 동시에 보이는지 확인
- 채팅 프롬프트에 내부 데이터 요약이 조건부로 주입되는지 코드 경로 확인
- 일정 화면 또는 요약에서 금융 연결 문구가 노출되는지 확인
- 기존 일반 지식 질의 흐름이 깨지지 않는지 정적 검토
- 가능하면 단위 테스트 또는 최소 컴파일 검증 수행
- 빌드 불가 시 그 사유를 명시

### 완료 조건

- 홈 화면에 금융+일정 기반 인사이트가 추가된다.
- 채팅에서 내부 카드/정기결제/일정 요약 질의가 가능해진다.
- 일정 화면 또는 일정 요약에 금융 연결 정보가 반영된다.
- 기존 기능 회귀 없이 동작 경로가 유지된다.
- 수정 파일, 검증 결과, 남은 리스크를 보고한다.
