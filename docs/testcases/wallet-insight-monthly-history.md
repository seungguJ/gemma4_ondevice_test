# Wallet Insight Monthly History TC

## 목적

- 홈 화면의 `이번 달 인사이트` 제거가 카드/정기결제/일정 진입 흐름을 해치지 않는지 확인합니다.
- 카드 사용내역 인사이트가 당월에는 raw 후보를 사용하고, 월 변경 후에는 raw 로그를 남기지 않은 채 월간 요약만 유지하는지 확인합니다.
- 전월 대비 비교와 월별 변화 시각화가 정상적으로 표시되는지 확인합니다.

## 데이터 기준

- 현재 저장소에는 실제 런타임 `SharedPreferences` DB 파일이 포함되어 있지 않았습니다.
- 따라서 본 TC는 `app/src/main/java/com/example/gemma4ondevicetest/wallet/NotificationInboxStore.kt`의 `NotificationInboxEntry` 스키마와 `app/src/test/java/com/example/gemma4ondevicetest/wallet/WalletParserTest.kt`에 들어 있는 삼성 Wallet 대표 알림 문구를 기준으로 작성합니다.
- 대표 표본은 `스타벅스`, `이마트`, `쿠팡`, `올리브영`, 승인취소, 광고/포인트/계좌이체 제외 케이스입니다.

## TC 목록

### TC-01 홈 화면에서 이번 달 인사이트 블록이 보이지 않는다

- 사전조건: 앱 실행, 홈 화면 진입
- 절차:
1. 홈 화면 첫 진입 상태를 확인한다.
2. 카드 사용내역, 정기결제 후보, 채팅, 일정 카드만 노출되는지 본다.
- 기대결과:
1. `이번 달 인사이트` 또는 동등한 요약 블록이 존재하지 않는다.
2. 홈 화면의 핵심 진입 카드 구조는 유지된다.

### TC-02 당월 raw 후보로 카드 인사이트를 생성한다

- 사전조건: 2026-06 Wallet raw 로그가 inbox에 적재되어 있고 `subscriptionEligible=true`, `cardInsightEligible=true`로 표시됨
- 절차:
1. 카드 인사이트 분석 워커를 실행한다.
2. AI 분석 입력이 정기결제 후보와 동일한 집합인지 확인한다.
3. 결과 리포트를 조회한다.
- 기대결과:
1. 승인/결제 후보만 분석 대상에 포함된다.
2. 광고, 포인트, 이체, 취소 전용 알림은 후보에서 제외된다.
3. `CardExpenseInsightReport.monthKey == 2026-06` 이어야 한다.
4. `categoryBreakdowns`, `topMerchants`가 채워진다.

### TC-03 전월 raw 로그는 지우고 월간 인사이트 요약만 남긴다

- 사전조건: 2026-06 리포트가 존재한 상태에서 시스템 월을 2026-07로 넘긴다
- 절차:
1. `NotificationInboxStore.ensureCurrentMonth()` 또는 동등한 월 경계 진입 경로를 실행한다.
2. 카드 인사이트 저장소를 다시 읽는다.
- 기대결과:
1. inbox raw 엔트리는 2026-07 기준으로 초기화된다.
2. 2026-06 raw 로그와 파생 후보 상태는 남아 있지 않다.
3. `CardExpenseInsightStore.loadHistory()`에는 `2026-06` 스냅샷이 남아 있다.
4. 남아 있는 값은 `totalAmount`, `totalCount`, `categoryBreakdowns`, `topMerchants`다.

### TC-04 카드 사용내역 화면에서 전월 대비와 월별 변화를 표시한다

- 사전조건: 당월 리포트 1건, 전월 히스토리 1건 이상 존재
- 절차:
1. 카드 사용내역 > 인사이트 탭으로 이동한다.
2. `월별 비교`와 `월별 변화` 영역을 확인한다.
- 기대결과:
1. 당월 합계와 건수가 보인다.
2. 전월 대비 금액/건수 증감이 보인다.
3. 최근 월 히스토리 카드가 최신순으로 최대 6개 노출된다.

### TC-05 채팅 내부 데이터 질의에 전월 비교가 포함된다

- 사전조건: 당월 리포트와 전월 히스토리 존재
- 절차:
1. `이번 달 카드 소비 어때?`와 유사한 프롬프트를 입력한다.
2. 내부 데이터 컨텍스트 구성을 확인한다.
- 기대결과:
1. 이번 달 카드 합계와 대표 카테고리가 포함된다.
2. 인사이트 후보 합계와 전월 대비 금액/건수 변화가 포함된다.

### TC-06 월간 히스토리 정합성

- 사전조건: 12개월이 넘는 월간 히스토리 존재
- 절차:
1. 서로 다른 월 스냅샷을 순차 저장한다.
2. 동일 월 데이터를 다시 저장한다.
- 기대결과:
1. 히스토리는 최신 월 기준 내림차순이다.
2. 동일 `monthKey`는 덮어쓰기 된다.
3. 최대 12개월까지만 유지된다.
